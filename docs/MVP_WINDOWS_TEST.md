# Windows v0.4.0 多 Agent 用量测试

## 安装

若旧版工作台正在运行，先在网页点击“关闭工作台”。从 [GitHub Releases](https://github.com/zznmdhz/agent-workbench/releases) 下载 `AgentWorkbench-Setup-0.4.0-Windows-x64.exe`，双击安装。从开始菜单打开 **Agent Workbench**，浏览器会自动打开 `http://127.0.0.1:8765/`。首次在网页创建至少 12 位密码，无需命令窗口。若电脑上已有 v0.3.0，直接安装新版即可继续使用原工作台数据；新来源第一次读取可能需要几十秒。

## 测试步骤

1. **看来源：** 页面“数据来源与覆盖”显示 Codex、Claude、Hermes 三项，各自显示本机最早／最晚记录和读取状态。若某项未发现来源，先确认该 Agent 在这台电脑留下过原生记录。
2. **查完整时间段：** 将开始日期设为 `2026-01-01`，结束日期设为今天。页面应显示跨月趋势与各 Agent 总量；一月到最早原生记录之前是 0，不能当成工具截断。再试任意较短起止日期，以及“今天／近 7 天／近 15 天／全部历史”快捷按钮。
3. **切 Agent 与模型：** 分别选“全部 Agent”、Codex、Claude、Hermes。各来源卡可以点击；模型表中的行可以点击。主卡、趋势、模型与会话应一起变化。
4. **核算 Token：** `新输入 + 缓存读取 + 缓存写入 + 输出 = 处理 Token`。Codex 原生日志中的输入已含缓存读取，页面会拆开显示；Claude/Hermes 各自原生的缓存读写会单列。Claude 来源卡若显示缓存字段缺失，则其总量仅为已记录部分，不能推断缺失值为 0。费用仍未计价，不代表免费。
5. **核对 Hermes 精度：** 选择 Hermes 后，处理总量应出现在“未分配日期”一行，而非伪造每日数据。若会话模型汇总跨越所选区间的边界，页面显示“暂未计入”的条数；扩大到完整覆盖该记录的区间后，它才计入。
6. **查看会话：** 点击 Codex/Claude 会话应显示逐请求用量；点击 Hermes 会话显示会话／模型汇总，并明确说明它不是逐请求记录。关闭详情后可继续筛选。
7. **重开：** 点击“关闭工作台”，再从开始菜单打开；数据和登录状态应保留。

## 数据边界与反馈

当前版本只读本机原生记录。某段时间显示 0，可能是来源尚未开始记录，也可能是真正没有使用；先看来源卡的最早日期。Codex/Claude 原生日志可按请求归属；Hermes `state.db` 当前仅保存可用的会话／模型累计用量，跨查询边界的记录不能可靠拆分。模型价格、完整对话、文件及跨设备功能不在本版验收范围。

如发现数字异常，请记录筛选的起止日期、Agent、模型、来源状态和异常卡片，在 [GitHub Issues](https://github.com/zznmdhz/agent-workbench/issues) 提交脱敏截图。不要上传原始会话文件、数据库或密码。
