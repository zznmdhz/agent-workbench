# 跨 Agent 工作台：开发实施与移交计划

版本：v0.2 执行补充｜日期：2026-09-23｜适用对象：后续开发任务中的 GPT-6 Sol

本文件把原 PRD v0.1 拆成可交付的工作包。它是实施计划，不是开发完成报告。当前只交付规划，不创建产品代码、不启动采集器、不部署 NAS，也不替用户修改 Codex 或 Hermes 配置。

产品源码应进入一个新的独立仓库。`B:/Codex/outputs/agent-workbench-planning/2026-09-23/` 是规划包目录，不是源码仓库；当前 DraftDock 项目也不是默认开发位置。新仓库位置由后续开发任务确定。

## 1. 开发时的阅读顺序与约束

1. 阅读原 PRD，理解用户目标和能力边界。
2. 阅读 [02_EXECUTION_SPEC.md](02_EXECUTION_SPEC.md)，以其中冻结的身份、事件、指标、同步和接口契约实现功能。
3. 按本文件的工作包推进，每个包同时交付实现、验证证据和限制记录。
4. 用 [04_ACCEPTANCE.md](04_ACCEPTANCE.md) 验收。原 PRD 的 AT01–AT18 是原始需求锚点；扩展用例及最终判定以 04 为准。

若文件间出现冲突，先记录具体条款，并按本包已经冻结的阶段范围修正同一次交付涉及的文档；不得在实现中悄悄选择另一套口径。当前冻结范围如下：

| 阶段 | 交付范围 | 不计入该阶段的能力 |
| --- | --- | --- |
| P0：来源与工程验证 | 实际来源探针、能力报告、样例契约、最小中心接收验证、环境与网络证据 | 完整产品界面和全量历史导入 |
| V0.1：双机 MVP | 双机同步、设备/Agent/模型筛选、统计下钻、简化三栏、30 分钟活动分段、中文搜索、基础路径映射与复制、部署和恢复 | 交接包、文件版本核验、RAM、原生跨机恢复 |
| V0.2：交接 | 上下文包、文件版本检查、新会话手工绑定、接续与分支关联 | 自动向 Agent 窗口发消息、任意命令执行、运行进程迁移 |
| V0.3：资源 | 可验证的进程级 RAM、资源采样与降级、必要的文件关系增强 | 原生集成和 AI 摘要仍是可选项目，不是本阶段完成前提 |

双机是 MVP 的真实验收范围。Codex、Hermes 按两台设备的实际安装与使用组合验证：未安装的组合登记为“不适用”，不得生成模拟会话凑齐四种组合；实际使用的来源缺失时，不得将该项登记为通过。

未连接 Mac 或 NAS 时，继续完成本机可做的工程任务、契约测试和模拟网络故障测试；相关实机门禁保持“待实机”，不能用截图、fixtures 或本机 Docker 代替双机/NAS 验收。

## 2. 状态与门禁判定

每个工作包只使用以下状态，并保留证据链接：

- `NOT_STARTED`：尚未开始。
- `IN_PROGRESS`：正在实现或验证。
- `LOCAL_VERIFIED`：本机工程检查通过，尚有必须的目标设备证据。
- `AWAITING_REAL_MACHINE`：明确依赖未取得的 Mac、NAS 或来源运行环境；必须写出缺少什么以及可继续的工作。
- `PASSED`：该包全部验收条件和所需实机证据齐全。
- `FAILED`：实际执行后未满足验收条件，已记录复现与下一步。
- `NOT_APPLICABLE`：有事实依据的不适用，例如该设备未安装某 Agent；不能用于跳过用户已要求的双机能力。

阶段报告可显示“本机工程验证完成，实机验收待补”；只要强制实机项未通过，阶段总状态就不能写“已验收”。测试用的合成数据必须标明 synthetic；真实来源的脱敏 fixture 必须保留可验证的来源版本与采集方式。

## 3. P0：来源与工程验证

### P0-01 建立独立工程与可运行命令入口

- **依赖**：已确定新的源码仓库目录；已经阅读 02/04。
- **工作**：建立 `collector/`、`server/`、`web/`、`shared/`、`tests/`、`deploy/`、`docs/`；Python 使用 uv，前端使用 pnpm。固定运行时、依赖和锁文件；配置本地开发和检查命令。实现本文件第 7 节命令的帮助与必要初始入口。
- **产物**：运行说明、配置示例、锁文件、CLI 帮助、最小 smoke test、忽略真实日志和凭据的仓库规则。
- **通过条件**：新环境按说明能启动 CLI 和最小服务；无真实来源时明确显示未配置；不伪造已连接设备或业务统计。
- **证据**：运行版本、实际命令、退出码、最小响应结果。此包可在本机独立完成。

### P0-02 编写只读探针并逐来源运行

- **依赖**：P0-01。
- **工作**：发现或显式配置实际 Agent 数据位置、Profile、版本和运行环境。读取有限的会话/轮次/用量/文件关系样本，验证读取是否覆盖用户实际入口。支持 Codex 与 Hermes；每个适配器保留来源版本和字段依据。
- **产物**：每个来源的 `capabilities.json`、`capability-report.md`、来源配置、错误与缺失说明。
- **通过条件**：每个实际使用组合至少读取一条历史会话和一轮新任务；能区分读取到、规则估算、缺失、不兼容。读取不修改源库、不调用会自动迁移源数据库的初始化逻辑。
- **实机要求**：Windows 和 Mac 的来源证据分别记录。当前只能运行 Windows 时保留 Mac 待验证项，同时继续后续通用工程。

### P0-03 固化脱敏样例和接入契约

- **依赖**：P0-02 已有至少一种真实来源样本；另一来源未到位时可先冻结公共字段，保留其适配验证状态。
- **工作**：将来源记录转换为 02 的事件与事实结构。建立正常完成、失败/取消、追加输入、模型变化、累计用量、历史缺失、晚到、镜像/分叉等 fixture；样本不足的情形用明确标注的合成 fixture 验证算法，但不据此宣称来源支持。
- **产物**：`tests/fixtures/<agent>/<version>/`、字段映射表、fixture 元数据、最小契约测试、能力差异记录。
- **通过条件**：fixture 可重复解析；来源位置与事件身份可追溯；真实敏感文本、密钥和认证目录未进入仓库；未知字段不默认为零。
- **限制**：事件ID、修订、时间和计数器规则按 02 实现，不在适配器内另造一套口径。

### P0-04 核实目标部署与两端网络

- **依赖**：可访问目标设备；可与 P0-02/P0-03 并行。
- **工作**：记录 NAS 真实型号、CPU、内存、空闲资源、ZOS/容器能力、拟用本地持久卷、端口与备份位置；验证两端到临时中心或 NAS 的已授权网络路径和应用认证。不能仅以极空间客户端能浏览文件推断 API 可达。
- **产物**：`environment-report.md`、安装矩阵、连通性证据、资源预算配置、未验证项清单。
- **通过条件**：证据说明每个结论来自哪里；未接通的目标明确为待实机；没有修改 Agent 入口、同步活数据库或绕过网络策略。

### G0 门禁

**本机工程继续条件**：P0-01 完成，至少一条真实来源读取闭环成立，公共契约和测试入口可用。此时可以开始 V0.1 通用实现。

**P0 完整通过条件**：两端实际使用来源的历史/新任务证据、能力表、NAS/网络检查均完成。核心字段不足时先调整适配器或降级声明，禁止伪造数据填补缺口。P0 未完整通过，不阻止独立本机工作，但会阻止宣称 G1 已通过。

| CLI与服务健康 | `uv run awb --help`；`uv run awb server --config .local/server.toml` | 启动本工具服务；不连接或修改未经配置的Agent |
| 来源只读探针 | `uv run awb probe --config .local/collector.toml --output .local/reports/probe` | 生成capability报告；能力缺失不会被写成支持 |
| 有界历史导入 | `uv run awb collect --once --config .local/collector.toml` | 已授权来源进入outbox；日志只显示必要元数据 |
| 持续采集 | `uv run awb collect --watch --config .local/collector.toml` | 增量采集和批量上传；停止/重启后可恢复 |
| 诊断 | `uv run awb doctor --config .local/collector.toml --output .local/reports/doctor` | 检查来源、中心认证、队列、时钟/网络；不在报告输出令牌 |
| 后端与契约测试 | `uv run pytest` | 执行本机可运行的测试；实机测试应显式标记和单独报告，不能因跳过而算实机通过 |
| 前端检查与构建 | `pnpm --dir web lint`；`pnpm --dir web test`；`pnpm --dir web build` | 关键交互验证和生产构建通过；具体脚本由P0建立 |
| 前端开发 | `pnpm --dir web dev` | 连接本地中心API；fixture模式有明确标识 |
| 部署 | `docker compose -f deploy/compose.yml up -d --build` | 在明确部署目标上构建/启动；NAS运行证据须来自NAS，不由本机启动推断 |
| 一致性备份 | `uv run awb backup --config .local/server.toml --output .local/backups` | 生成匹配数据库与版本的可恢复备份，返回实际产物清单 |
| 恢复演练 | `uv run awb restore --config .local/restore-test.toml --backup <备份路径>` | 默认先恢复到隔离测试数据目录；校验核心统计、索引重建和重传幂等 |
| V0.2导出 | `uv run awb handoff export --config .local/client.toml --session <session_id> --target-environment <environment_id> --output .local/handoffs` | 对已保存截止点导出包；要求适当读取权限，不能复用只有写权限的采集令牌 |

`backup/restore` 的容器内用法与宿主命令应在部署说明中同时给出。恢复到现有生产数据目录属于另外的明确操作，不能把演练命令默认指向生产覆盖。

设备配对、令牌输入和登录应使用安全的交互或本机受保护配置，示例命令不能要求用户把真实令牌写入命令行历史。Windows自启动与macOS登录启动命令在实机验证后写入对应安装说明，不在未知系统版本上预先宣称已可用。

## 10. 交给 GPT-6 Sol 的执行规则

- 每次先选择满足依赖的具体工作包，报告它的产物和验证结果；不要以“页面已画出来”替代后端事实链路。
