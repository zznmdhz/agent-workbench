# 验收规范与数字测试集

版本：2026-09-23。对象：跨 Agent 工作台 PRD v0.1 的补充执行规格。

本文定义开发必须证明的结果，不表示已经通过测试。阶段与执行规格、工作包统一：**P0 数据探针；V0.1 核心采集、统计与双机查询；V0.2 交接；V0.3 RAM 与资源增强**。P0 只验证真实来源和能力边界，不要求已经交付完整 MVP 或完成 NAS 部署。

## 1. 验收口径与证据要求

### 1.1 固定计算约定

- 生产报告默认全局时区为 `Asia/Hong_Kong`，不同设备不得各用各的时区拼日报。日期筛选采用半开范围 `[start,end)`；事实保留 UTC 时刻、来源原始偏移及时间依据。日边界先由报告时区转换成 UTC，再裁剪区间。
- 精确累计响应区间时长纳入 `completed / failed / cancelled` 中起止完整可信的顶层轮次。已包含在父轮内的子轮不再次累加。这里包含可观测轮次内的工具、审批或排队等待，不宣称全部是模型计算时间。
- `running / stale / unknown` 单列；缺少可信终点不能进入已结算时长。已观察到的运行下界与当前状态可以展示，但不能自动变成已确认完整时长。
- 均值、中位数、P95 只使用时间完整可信的 `completed` 顶层轮次，整轮按开始日归入样本；时长日分布仍按日边界切分。P95 使用 nearest-rank：排序后第 `ceil(0.95*n)` 项；空样本返回 NULL。
- 模型筛选下的可归属轮次时长，只纳入能够完整证明为该单一模型的轮次。`mixed / unknown` 时间单列、不按 Token 比例分摊、不填 0。若另提供模型请求区间时长，必须使用不同字段与标签。
- Token 缺失使用 NULL；缓存、推理等已含在 input/output 内的子字段不再次相加。逐请求事实与覆盖相同请求的累计快照不重复计账。
- 累计快照首值仅作为日期未分配的历史余额；只有同 epoch 的明确零起点及完整已知窗口，才可将首值全额作为该窗口内增量。相邻差值仅在覆盖区间完整落于同一报告日时归日；跨日进入带区间的未分配桶。不得使用接收日或后一个快照日期代替消费日。
- 计数器回退没有显式 reset/epoch 证据时隔离；同事件键不同内容不覆盖。不能自动开启新 epoch，也不能把负差值裁成 0 后继续当作可信累计。
- 统计必须提供数量、口径、证据等级和缺口。NULL、0、未同步、尚未索引、来源不支持和解析失败是不同状态。

### 1.2 证据分级

| 证据类别 | 可以证明 | 不可替代 |
| --- | --- | --- |
| 合成数字 fixture | 公式、状态机、异常分支和重复导入的确定性 | 真实 Agent 数据字段存在、双机已连通 |
| 脱敏真实来源 fixture | 特定版本、Profile、运行入口的解析结果 | 其他未探测版本或设备的兼容性 |
| 实机记录 | 当前设备、网络、NAS 的实际运行情况 | 长期性能或未测试环境的保证 |
| 截图/录屏 | 页面状态、交互定位和布局 | 数据完整性、正确去重和安全边界 |

每项验收记录至少包含：用例 ID、阶段、输入版本或 fixture 哈希、操作步骤、期望、实际、证据路径、执行环境、状态。测试结果使用 `PASS / FAIL / BLOCKED / NOT_RUN`；这是验收结果枚举，不是 03_IMPLEMENTATION.md 中的工作包状态。`BLOCKED` 必须写明缺少的设备或访问条件，不得写为通过。

适配器 fixture 应覆盖每种实际使用的 Agent、版本和运行入口。没有使用 Hermes 的设备不要求伪造 Hermes 数据；尚未能访问的 Mac/NAS 不得以 Windows 模拟器代替真实验收。

## 3. 十二组必须自动验证的数字 fixture

下述时间若未带偏移均为报告时区 `Asia/Hong_Kong`。各 fixture 独立运行；不能将不同 fixture 的计数加在一起。每组均需验证首次投影、重复投影和从原始事实全量重建三者结果一致。

### F01：稳定身份、镜像、合法重复文本与字符数

输入：Mac 已核验来源 `S1` 中，原生事件 `E1` 对应 120 Token、`E2` 对应 80 Token。每条事件分别被 Mac 和 Windows 采集器各上传 3 次。两条已接受的用户输入文本都为 `A\r\n🙂中`，且消息 ID 不同；其中 `\r\n` 指实际 CRLF。

期望：

- 12 次观察形成 2 条消费事实，Token 合计 `120+80=200`。
- 已确认执行归属：Mac 200、Windows 0。Windows 上传不产生 Windows 消耗。
- 每条输入归一 CRLF 后为 `A`、LF、`🙂`、`中`，计 4 个 Unicode 码点；输入消息 2 条、字符 8。不能因文本相同只保留一条。
- 若只知道日志存放在 Mac 而无执行设备证据，改为 `unknown=200`；不得用 observer 强填 Mac 或 Windows。
- 对同一事件的重观测元数据不得改变消费事实 ID；一个观测列表可保留多条采集证据。

### F02：累计快照差分及被包含的 Token 子字段

输入：同一消费计数器 epoch 已证明在当日 09:00 从 0 开始；09:01、09:02、09:03、09:04 的累计值分别为 100、150、150、220。末值 input=150、output=70；cached_input=60 已含在 input，reasoning_output=20 已含在 output。

期望：新增分别为 `100、50、0、70`，同日合计 `220`。不得把快照相加成 `620`，也不得加子字段得到 `300`。末快照重复 10 次，合计仍为 220。

反例：去掉已验证的零起点证据，则首个 100 进入历史未分配余额；后续当日可分配新增为 `50+0+70=120`，累计观测仍为 220。不能将初始 100 擅自归当天。

### F03：跨日差值、历史余额与迟到快照重建

输入：9/22 23:50 累计 100；9/23 00:20 累计 160，无初始零点。之后收到源序号介于两者之间、发生于 9/22 23:55 的累计 120。

期望：

1. 中间快照未到时：历史余额 100 日期未分配；差值 60 覆盖午夜，跨日未分配；两天的确定日用量都不因这一差值增加。
2. 中间快照到达后：9/22 可确定新增 `120-100=20`；跨日未分配 `160-120=40`；历史余额仍为 100。
3. 可核对总量：`100+20+40=160`。旧的派生差值 60 被替换为 20 和 40，不保留并再次累加成 220。
4. 9/23 不因后一个快照位于该日而得到确定的 40 或 60 Token。

### F04：有证据的重置、无证据的回退与同键冲突

输入 A：epoch1 当日明确从 0 开始并累计到 100；存在明确 reset 记录，epoch2 同日明确从 0 开始并累计到 20。

期望 A：同日报告为 `100+20=120`，两个 epoch 分开留证据。

输入 B：只有 100→20 两个快照，没有 reset/epoch 证据。

期望 B：最后可信已知量为 100；后续完整性为异常/未知。不得计算 120；不得将 -80 裁为 0 后声明数据完整。

输入 C：同一事实键已保存 payload 中的 100，又收到同键不同 payload 的 110。

期望 C：原始可信事实保持 100；冲突数量增加 1；110 保存在隔离记录中，不能覆盖或直接新增 110。

### F05：分叉继承与真实重新读取历史

输入：父分支已核验累计 500；子分支有明确 inherited baseline=500 和祖先消息引用，后续累计 600；之后一条新的、原生请求 ID 不同的请求为读取交接历史消费 2,000。

期望：子分支新增 `600-500=100`；父子合并为 `500+100=600`；新请求后为 `600+2000=2600`。继承消息不增加当日用户输入数；新用户提交和新请求依正常规则计数。

反例：没有分叉锚点或 inherited baseline 证据时，子分支的 600 标记为覆盖范围未核验。不能把父子合计成 1,100，也不能只凭相同文本擅自断定合计为 600。

### F06：并行、顶层与子轮、远程操作设备

输入：Mac 顶层轮次 A 为 09:00–09:10，A 的子轮为 09:02–09:07；Windows 顶层轮次 B 为 09:05–09:15。A/B 均完整完成。用户从 Windows 远程操作 A，但执行仍在 Mac。

期望：

- 顶层累计 `600+600=1200` 秒，即 20 分钟；不能再加子轮的 300 秒。
- 全设备区间并集为 09:00–09:15，共 900 秒，即 15 分钟。
- Mac/Windows 各自区间并集均为 600 秒；二者不能直接相加充当全设备并集。
- A 的执行归 Mac；Windows 是操作入口，不改变 A 的 600 秒归属。

### F07：终态先到、历史补传与受影响日期

输入：9/22 的源 seq2 为结束 10:10，先于源 seq1 的开始 10:00 抵达；两条均于 9/24 上传，最终可确认同一顶层 completed 轮次。

期望：仅收到结束时，精确时长为 NULL，状态显示“缺少开始记录”；补齐后得到 `600` 秒，进入 9/22。9/24 的该项执行新增为 0；接收时间只影响同步面板。受影响的 9/22 缓存、会话活动索引和样本统计均重建。

### F08：半开日界、跨午夜与来源 DST

输入 A：9/22 23:55–9/23 00:05，一个完整 completed 顶层轮次。

期望 A：9/22 300 秒，9/23 300 秒；两日累计 600 秒。均值样本整轮 600 秒归 9/22，9/23 没有因此新增一个 completed 样本。“新开始轮次”分别为 1、0；“当日有执行轮次”分别为 1、1。

输入 B：来源纽约时间 `2026-11-01T01:30:00-04:00` 到 `2026-11-01T01:30:00-05:00`。

期望 B：UTC 为 05:30–06:30，报告时区香港为当日 13:30–14:30，时长 `3600` 秒；不能因为来源墙上时钟读数相同而计算为 0。

输入 C：有可靠请求开始时刻的请求在香港 9/23 00:00:00 消费 50 Token。

期望 C：查询 `[9/22 00:00,9/23 00:00)` 不包含它；查询下一日包含 50。范围终点事件不能两天重复计数。

### F09：混合模型与单模型完整归属

输入：轮次 R1 完整响应 600 秒；模型 A 请求区间为相对起点 0–60 秒，消费 100 Token；模型 B 为 180–300 秒，消费 300 Token。R2 为能够完整证明仅使用 A 的轮次，响应 120 秒，其中 A 请求区间 40 秒，消费 50 Token；其余 80 秒有已知工具等待。R1/R2 为不重叠顶层轮次。

期望：

- 全部 Token 为 `100+300+50=450`，累计响应时长 `600+120=720` 秒。
- 筛 A 时 Token 为 `150`；可唯一归属给 A 的整轮响应时长为 R2 的 `120` 秒。
- 含 A 的 mixed 轮次时间为 R1 的 `600` 秒，单列为未分摊 mixed 时间，不能填 0 或归 A。
- 若提供请求耗时指标，A 为 `60+40=100` 秒、B 为 `120` 秒；该指标不可与整轮时长混称。
- R1 的未被模型请求区间覆盖部分为 `600-60-120=420` 秒；不得按 Token 比例给 A 分配 150 秒、给 B 分配 450 秒整轮时长。
- 若 R2 只知道最后配置模型 A，而不能证明整个轮次用过哪些模型，则 R2 也进入 unknown 模型时长，A 的可唯一归属时间为 NULL，不伪装成已证明的 120。

### F10：完成样本、失败取消与开放轮次

输入：completed 轮次 60、120 秒；cancelled 完整轮次 600 秒；failed 完整轮次 180 秒；另有一条已知 failed 但缺结束时刻的轮次；另有一条 10:00 开始、10:05 最后确认仍在执行、随后断联的轮次，11:00 查询。

期望：

- 已结算累计时长为 `60+120+600+180=960` 秒。
- 完成统计样本 n=2，均值 90、中位数 90、P95 120 秒。
- 5 条已知终态顶层轮次中，4 条有完整可信时长，终态时长覆盖为 `4/5=80%`。completed 精确样本覆盖为 `2/2=100%`，两种分母明确区分。
- 缺结束的 failed 时长为 NULL；断联轮次显示 stale/状态待确认，不进入 960 秒。
- 可显示“截至 10:05 已观察运行至少 300 秒”；不能在 11:00 自动结算为 3,600 秒。

### F11：连续收据水位、响应丢失和坏记录终止处置

本组 `outbox_seq` 属于本工具传输流，不是原 Agent 的源序号。以下数字只针对同一 `(collector_id,outbox_epoch)`。

步骤与期望：

1. 服务端先持久接收 1、2、4；连续可确认水位为 2，接受事实数 3。不能用最大值 4 当水位。
2. 响应丢失后重复上传 1、2、4；事实数仍为 3，水位仍为 2。
3. seq3 内容无效。仅返回 4xx 或解析错误而没有持久保存原始负载与原因时，水位保持 2；客户端保留待传记录。
4. 服务端持久隔离 seq3 的负载、哈希和原因并返回隔离收据；客户端把原始项及隔离收据写入自己的 deadletter 后，发出显式终止处置确认。服务端持久记录该处置后，连续传输水位可到 4。
5. 最终为 3 条统计事实、1 条隔离坏记录、4 条已终结传输项。坏记录不进入 Token、消息或耗时统计。水位 4 只证明传输项已有持久去处，不证明 4 条都是有效数据。
6. 在客户端 deadletter 提交前崩溃，重启必须继续第 4 步，不能悄悄丢弃 seq3。处置确认响应丢失后重试也是幂等的。
7. 投影水位落后于传输水位时，页面分别显示已接收与已索引；隔离数始终可见，不能以水位到 4 宣称来源统计完整。

接口可实现为两阶段 resolved receipt；字段名以统一 API 合约为准，但上述确认顺序不能削弱。服务端不得把未经持久隔离的报错当作可终结收据。

### F12：本地事务边界与中心恢复后的补齐

输入：源游标为 100；采集器读取到记录 101–120，共 20 条。

期望：

- “写 outbox＋更新源游标”的本地事务提交前崩溃：游标仍为 100，这批 outbox 不存在；重扫得到 20 条。
- 事务提交后崩溃：游标为 120，outbox 有 20 条；重启后发送，不能跳过或重新制造 40 条事实。
- 中心原已确认到 120，恢复的备份只含到 100：必须通过恢复代际与水位协商，重放 101–120，使中心事实恢复为 120 条；重复重放结果仍为 120。
- 若已确认 outbox 与原始来源都不再保存 101–120，报告不可恢复缺口 20 条并判本次“无缺口恢复”失败；不得仅因服务能启动判 PASS。

## 5. 同步、删除与恢复验收

| ID | 操作 | 通过标准 |

| D01 | 删除一条已导入会话的中央内容，然后对未删除的源日志重扫、重传旧批次 | 中央正文、搜索索引、派生摘要/交接缓存按删除范围清除；原 Agent 与原工作文件不变。最小删除墓碑阻止旧副本自动复活；用户明确重新导入才能按产品规则解除。 |
| D02 | 删除后恢复一份删除前备份 | 恢复流程重新应用备份后的删除决策，或在无法证明应用成功时阻止被删内容对外可见。不能因恢复旧备份自动撤销隐私删除。界面说明备份轮换何时清除旧内容。 |

删除墓碑保留范围、删除决策的独立恢复方式和 outbox 保留期应在运维说明中写明；没有实现和验证前，相关恢复用例为 `NOT_RUN/FAIL`，不得用“备份存在”替代。

## 9. 阶段出口与交付记录

**P0 出口**：E01 的真实来源探针交付运行入口、版本、Profile、字段证据、脱敏样本、能力报告和缺口；每个实际使用来源至少核查一条历史会话与一轮新任务，明确哪些字段支持、推算、缺失、不兼容或尚未验证。不能修改源 Agent 来制造支持。不可访问的来源保持 unverified/BLOCKED，可并行推进已验证来源的开发；不要求 P0 已完成 Web MVP、双机持续同步、全部数字测试或 NAS 部署。

**V0.1 出口**：F01–F12、E01–E06 回归、W1、T1、S01–S04、D01–D03、Q01–Q04、Q06–Q07 及适用的 L/U 项通过；两台真实设备向同一中心形成至少一个可追溯闭环；真实 NAS 部署与恢复完成。未获得某台设备访问时，可交付已完成软件和采集包，但“双机/NAS 验收”必须维持 `BLOCKED`，不能把 V0.1 写成实机全通过。
