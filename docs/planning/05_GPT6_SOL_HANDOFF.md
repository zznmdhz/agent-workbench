# 给 GPT-6 Sol 的开发启动说明

以下内容可直接作为开发任务。请把本规划包整个文件夹提供给模型；不要只传这一页而丢掉执行契约和验收样例。

---

请开发“跨 Agent 工作台”：Windows、Mac 各运行只读采集器，收集用户实际使用的Codex/Hermes会话与可获得的执行/用量/文件信息，上传NAS中心服务，以Web统一查询。目标是按日期/设备/Agent/模型查看消耗，按当天活动回看三栏会话，并在下一版本生成可继续工作的上下文包。

阅读顺序：README.md → 01_REVIEW.md → 02_EXECUTION_SPEC.md → 03_IMPLEMENTATION.md → 04_ACCEPTANCE.md → 06_SOURCES.md → contracts目录。原PRD在source/，保留产品背景；本包明确的执行决策优先。

本任务是新项目。不要在DraftDock现有项目里开发，也不要覆盖其中未提交修改。若当前任务尚未绑定专用目录，先创建独立的agent-workbench源码目录并记录实际位置；不能把规划输出目录直接当已存在的应用。遵循新项目中的适用AGENTS.md。

执行范围包含P0、V0.1、V0.2、V0.3的既定工作包；按阶段交付，前一阶段真实门禁通过后继续。探索项（原生Remote/Handoff、AI摘要等）没有自动扩张为必做项。用户只要求首阶段时，以用户的新范围为准。

第一阶段先做来源清单、只读探针、标准事件、统计纯函数/同步状态机测试；然后接真实两端，再做页面和NAS部署。每个实际安装入口至少验证历史读取和新增轮次；保留Agent版本、schema指纹、脱敏样本及能力报告。不要为了采集实例化会迁移原库的Agent代码，也不要修改Agent认证或默认调用入口。

无法访问Mac或NAS时，可以继续独立的本机代码、fixture、打包与容器验证；把相应实机门禁保持pending，提供对方可执行的采集/诊断步骤和预期报告。不要用模拟双设备宣称真实双机已通过，不反复询问已经由规划冻结的常规产品选择。

必须落实这些规则：

1. 源事实身份与观察者分离，复制日志不改变执行设备；所有未知保留未知。
2. 累计/并行去重响应时长分开；父子轮次不叠加；混合模型轮次不按Token比例拆时间。
3. 消费用量不等于上下文占用；累计首值与跨日差值按规格进入未分配，不伪造每日历史。
4. 传输序号、源序号、接收与投影水位分开；仅连续可确认收据推进ACK；隔离坏项有持久处置闭环。
5. 同键冲突不覆盖，合法消息修订产生新事实；统计投影可以从事实重建。
6. V0.1就交付简化三栏、活动日期回看、中文搜索和基础路径映射；V0.2再做冻结交接包与目标会话绑定。
7. 文件名/路径存在不等于版本一致，目录已有文件不全部算会话产物。
8. 中央删除/排除后，离线补传和备份恢复不能复活正文；恢复还需重新协商server_epoch。
9. 所有性能目标必须用指定规模和真实机器测量；源码测试、模拟负载、实机测试分开报告。

实施中可自行决定常规库调用、样式细节和模块内部结构；涉及统计口径、范围、来源写入、隐私策略或大规模替换技术栈时，以实机证据记录ADR，并同步改规格/测试/迁移方案。新文件优先小步实现，代码审查后再推进依赖模块。

预期统一命令入口为`uv run awb`；Python使用uv锁依赖，Web使用pnpm锁依赖。这些是需要实现的产品命令约定，不是本规划包已经提供了可运行软件。

每阶段输出：代码与变更摘要、capability-report、verification-report、真实使用的fixture出处（已脱敏）、通过/失败/pending验收、已知限制与下一步。阶段完成必须引用04中的用例及证据，不能只说“已完成”。最终交付安装包/容器、启动与备份恢复说明，以及可复现的跨机查询/交接演示。

先开始P0和V0.1的最小纵向闭环；不需要重新写一份宏观PRD，不先搭品牌页面、微服务、多租户或统一聊天代理。
