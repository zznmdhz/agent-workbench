# Mac v0.6.0 测试说明

当前 Mac 应用由本仓库源码在本机生成，尚未作为 GitHub 安装包发布。它只读发现 Codex、Claude Code 和 Hermes 原始数据；归档底库保存在 `~/Library/Application Support/AgentWorkbench/data/`。

## 打开应用

1. 在仓库根目录运行 `bash packaging/build_mac.sh`，生成 `dist/mac/AgentWorkbench.app`。也可打开已安装的 `~/Applications/AgentWorkbench.app`。
2. 双击应用；浏览器应打开 `http://127.0.0.1:8765/`。若没有自动打开，可手动访问。
3. 页面左上角确认 `v0.6.0`。右上角“关闭工作台”可退出，再次双击即可重开。

首次读取大型 Codex 历史日志可能需要几十秒；以后按文件大小与修改时间增量更新。请等“同步中…”和“正在索引…”消失后核对结果。

## 建议核对

1. 在页面顶部确认本机电脑和 Sync_AI 同步目录状态；可切“全部电脑”与本机。初次回填会比后续增量扫描慢。
2. 在热力图区点“Token 用量／运行时间”，再切换“年／月／周／日”。同一日期范围和 Agent 筛选应保留；格子悬停或键盘聚焦应显示当前指标的数值。
3. 在“会话记录”选择一天，再试“近 7 天”及手动起止日期；切换全部、Codex、Claude、Hermes。输入关键词后左侧列表应自动筛选。左侧显示 Codex／Claude 原始记录大小或 Hermes 会话内容量，点“打开目录”应打开来源所在文件夹。选中会话后右侧标题显示用户提问轮次、Agent 用时和已确认文件数。
4. 在右侧“对话”切换“关键节点／完整详情”：前者保留用户输入和每轮最后的 Agent 回复，后者保留原始文字消息。长会话可翻页，窄屏可返回列表。
5. 在“文件与位置”核对原始日志路径、工作目录和文件操作时间。点“打开所在文件夹”应打开文件的父目录，而不打开文件本身；临时文件目录若已不存在，页面应给出错误。成功工具操作与待核实路径分开显示。Hermes 使用共享数据库，无法按会话分摊物理文件大小；页面只给出消息与工具字段内容量。口径见[会话导航与文件口径](project/SESSION_NAVIGATION_V0.5.3.md)。
6. 对照“全部 Agent 累计”和“自然经过（并行去重）”。若有并行运行，前者可大于后者。“已证实”仅包含完整 Codex 顶层任务；其余估算规则见口径文档。
7. 按 Agent 筛选时间；模型筛选仅应用于 Token。Claude 本机原始记录没有覆盖的日期可能为零。Hermes 的 Token 汇总不能分配到逐日格子，但其消息可用于估算时间。跨午夜任务应分别出现在两天。

顶部可选“全部电脑”或单台电脑。当前尚无 Windows 包时，全部电脑只显示 Mac；把 Windows 的 Sync_AI 路径配置到同一 Syncthing 共享目录后，再核对 Windows 数据是否进入本机底库。卸载 Agent 后，已归档的对话、Token 和文件索引应仍可查询；产出文件本身不会备份。计算规则和限制见[会话与时间口径](project/SESSION_TIME_V0.5.md)；同步说明见[底库与双机同步](project/DURABLE_ARCHIVE_SYNC_V0.6.md)。反馈问题时记录日期、Agent、来源状态和页面现象；不要把原始会话或未脱敏截图提交到 GitHub。

## 开发者检查

`bash packaging/smoke_mac.sh` 使用隔离空来源和测试数据库检查打包应用的服务、页面与用量接口。Windows v0.6.0 的安装、升级和自动更新仍需 Windows 实机验证。
