# 模型分析与会话检索（v0.7.0）

## 模型分析

用量日期、电脑、Agent 和模型筛选作用于模型报表。报表提供处理 Token、调用次数、单次平均处理量、缓存读取占输入比例四个指标，并以模型对比横条、份额环图、按日／周／月折线、24 小时调用柱图、输入与输出散点图、缓存率条图和可核对的明细表展示。

- “处理 Token”＝新输入＋缓存读＋缓存写＋输出。缓存命中率＝缓存读取 Token ÷ 全部输入 Token；它不是请求成功率。源记录缺字段时不会补造。
- Codex 和 Claude 按逐次请求时间进入趋势、频率和散点图。散点图最多均匀抽样 400 条，明细汇总仍使用全部记录。
- Hermes 仅有完整会话／模型汇总。完整落在所选范围的汇总参与模型总量、份额、缓存率和明细；不进入逐日、逐时或单次请求图。跨越筛选边界的会话不拆分。
- 不同 Agent 的“请求”和“调用”并非完全同一计量单位，跨 Agent 平均值仅供规模参考。
- 每个图最多用少数颜色区分模型；图旁保留文字标签及明细表，避免只能靠颜色辨认。

## 会话检索

按日期段、电脑、Agent 查看会话。关键词范围可选标题、对话内容、文件路径或全部；输入后自动搜索。可按最近／最早活动、文字多少、Agent 用时长短、记录大小、消息数、确认文件数排序，并设置最低文字量、最低 Agent 用时和“有确认文件”。清空筛选不会改动日期与电脑选择。

文字量是所选日期内已归档消息正文的字符数；Agent 用时沿用现有已证实／估算口径。文件数仅包含有来源证据的唯一文件路径。Codex／Claude 的记录大小是原始日志磁盘大小，Hermes 显示消息与工具字段量估算；不能把这些数值当作运行内存，也不宜跨来源直接比较物理占用。结果最多显示前 300 个，同时显示总匹配数。选中会话后仍在右侧查看对话与文件位置。

模型报表与会话检索读取 Workbench 自己的持久底库，因此已归档数据在 Agent 原始记录移除后仍可检索。产出文件本身只保留索引，不做备份。
