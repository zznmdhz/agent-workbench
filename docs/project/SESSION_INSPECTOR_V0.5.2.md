# 会话分栏、搜索与文件位置口径（v0.5.2）

## 交互

桌面端会话列表和详情左右并排；日期、Agent 与关键词控制列表，选中一条后右侧切换“对话／文件与位置”。窄屏先显示列表，进入详情后提供返回按钮。对话仍按所选日期范围分页；文件操作区显示该原生会话在日志中可找到的全部操作线索，可能早于或晚于当前查询日期。

搜索在停止输入 350 毫秒后请求本机接口。范围为所选日期内的会话标题、原始用户／Agent 文字内容、已索引的文件路径，以及 Hermes 工具调用字段。搜索结果注明命中类型；正文和路径索引只存储在这台电脑的工作台数据库，原始 Agent 文件只读。Codex／Claude 文件按大小、修改时间及解析器版本增量更新；短中文关键词也可搜索。新版本首次打开时需为旧日志建立一次本地索引，可能比后续打开慢。

## 位置与大小

- **Codex／Claude**：显示原生日志完整路径、来源报告的工作目录，以及当前原生日志文件磁盘大小。路径可复制后在 Finder／资源管理器定位。一个会话关联多个日志文件时大小相加。
- **Hermes**：显示共享 `state.db` 与来源工作目录。数据库文件大小不能可靠分摊到单个会话；页面另外显示该会话消息和工具字段的字节数近似值，明确不等于数据库占用。
- 这些值都是文件或文本的**磁盘／内容大小**，不是 Agent 进程 RAM。共享进程的历史 RAM 不能从会话日志倒推。

## 文件操作证据

列表按原始操作时间展示同一路径的多次记录；“已确认文件数”按路径去重。Codex 直接 `apply_patch` 只有调用与成功结果匹配才算确认；通过 `exec` 包装的嵌套补丁仅列为“待核实路径”。Claude 的 Write/Edit/MultiEdit/NotebookEdit 只有匹配到无错误的工具结果才列入；Write 可能创建或覆盖，统一标为“写入”。Hermes 的 `write_file`／`patch` 在打开详情时按该会话的工具调用和成功结果读取。页面另行检查文件**当前**是否存在和当前大小，不把当前状态当作当时的文件大小。

Shell 命令、外部程序、未留日志的操作以及部分工具格式不能自动证明文件归属。因此“没有文件记录”只表示当前可解析来源没有证据，不能解释为会话没有产出。当前页面提供可核实的历史和未核实线索，不承诺操作系统级完整文件变更历史。Mac 已做基础功能验证；Windows 路径和打包代码保持同步，仍需 Windows 实机验收。
