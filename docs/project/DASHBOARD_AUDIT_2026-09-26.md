# 总览页面与原 PRD 差距排查（2026-09-26）

依据：`docs/planning/跨Agent工作台_PRD_v0.1.md` 第 11–12 节，以及 `docs/planning/02_EXECUTION_SPEC.md` 第 7 节。验收范围是当前仅有的 Windows 本机环境；跨 Mac/NAS 的事实不能在单机上宣称通过。

| 原设计要求 / 用户反馈 | 排查结果 | 本次处理 | 仍需验收或开发 |
| --- | --- | --- | --- |
| 最近会话、时间线不能变成蓝色实心块 | `.panel>button` 将所有面板直属按钮误当主按钮 | 收窄 CSS 选择器；普通行恢复白底和悬停态 | Windows 安装版视觉点验 |
| 日期、设备、Agent、模型、时区联动 | 原网页仅有单日日期，统计固定香港时区；时间线没有筛选 | 增加单日/7/10/15 天、设备/Agent/模型/香港或 UTC；统计、会话和时间线传递相同筛选；多日改为逐日趋势 | 更多 IANA 时区、URL 保存筛选与后退历史 |
| 时间线分组并能点击轮次 | 原页面直接铺开最多 30 条，且样式误伤 | 单日默认显示 8 条，超出可展开且限制滚动高度；点击进入所属会话 | 精确定位到轮次锚点、拖动缩放、按设备/Agent 汇总泳道 |
| 主卡可下钻并显示依据 | 原卡为静态 `<div>` | 六张主卡可点开说明、覆盖数量和相关会话证据；可进入会话 | 对话内精确锚点、活动时间的跨会话并集贡献解释 |
| 输入/输出 Token 不能一直空白 | Codex `token_count.total_token_usage` 有输入/输出分项，但旧采集器只保留总值；Hermes 为会话总量，不能硬塞到某一天 | 采集 Codex 累计输入/输出并按同日连续快照算差值；首次升级一次性重新只读扫描历史日志回填；卡片明确标示数据依据 | 历史首个余额、跨日间隔仍不归入日值；Hermes 每日输入/输出仍需源端证据 |
| “累计计数差分”难懂 | 原卡只展示大数字，容易误当总消耗 | 从主卡移除该术语；输入/输出卡说明“会话累计计数差值”，总量差值放入每日趋势和设备对比且明确未采集状态 | 用真实日志与账单抽样对账，尤其缓存/推理 Token 的口径 |
| `github`、`Drive`、`Doc` 等会话名不明 | 这些是无标题会话的工作目录末级名称，被错误充当标题 | 主标题统一显示“未命名会话”，副标题明确“工作目录：…” | 用户自定义标题、源端标题覆写策略 |
| 用量趋势、设备对比 | 原网页缺失 | 7/10/15 天显示逐日轮次/Token 差值趋势；增加每设备轮次、耗时、字符、Token 对比 | 模型维度的可靠归属、更完整的覆盖率、设备离线水位展示 |

统计边界：输入/输出优先使用逐请求增量；没有该证据时才使用 Codex 会话累计计数的同日差值。首个快照是开头余额，跨日间隔不均摊。Hermes `session_model_usage` 是会话聚合量，不能伪造每日值。累计时间是可结算轮次的时间之和；活动时间是区间并集，设备内并集不能直接相加为全局并集。

当前交付仍不是原 PRD 的跨机完整版。会话三栏的活动片段/文件资源页签、URL 深链、Mac/NAS 实机同步与交接、完整状态矩阵及 schema 迁移体系仍在路线图中。Windows 版可以独立使用，但这些条目需要各自的实施与验收证据。
