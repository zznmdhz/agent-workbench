# Windows MVP 重构：用量与会话统计

状态：2026-09-26 重构基线。此文档替代旧路线图中对下一版的范围定义；v0.2.4 保留为历史版本，不作为“完整版”验收依据。

## 产品决策

用户当前的第一任务是回答：**某天／一段时间内，各 Agent 和模型实际处理了多少 Token、缓存占多少、发生了多少请求和会话，这些数字能否核对？** 先做这个闭环。旧会话正文、文件、跨机、交接、资源、复杂设置退出主导航；保留现有数据与后端，待 MVP 通过后分期评估，不删除用户内容。不得在发布说明中把隐藏功能称为完成。

## CC Switch 拆解结果

参考 `farion1231/cc-switch` 的 MIT 源码，固定审查提交 `e0f70019b2758f5b6b9a04dd60e4689481a0c0ac`：

| 能力 | CC Switch 实现 | 本产品 MVP 取舍 |
| --- | --- | --- |
| 来源 | 代理请求日志和各 CLI 原生会话日志共用一张使用账本；Codex 解析 `~/.codex/sessions` 与归档 JSONL | 第一阶段先独立解析本机 Codex JSONL，不接管网络代理，不依赖 CC Switch 安装；其他 Agent 只有证明请求级来源后才纳入 Token 总量 |
| Codex 请求 | `last_token_usage` 优先；缺失时从 `total_token_usage` 高水位求差；依据 `turn_context` 关联模型 | 保留请求身份、时间、模型、原始输入／缓存／输出与源文件偏移；未知模型原样标记 |
| 去重 | 相邻/同来源重复快照、fork 继承父日志的重播前缀、物理 rollout ID + 非零事件序号；代理与日志相交时去重 | 首阶段实现日志内去重和 fork 排除；没有代理数据，不需要跨来源去重；不确定父关系的文件暂缓计数并显示缺口 |
| 统一输入 | Codex 的 input 已包含缓存读取；按 `fresh = input - cache_read` 归一；Claude 类来源语义不同 | 不把缓存再加到原始输入。页面显式展示新输入、缓存读取、输出、处理总量；未来接 Agent 必须声明输入语义 |
| 费用 | 模型价格 × 各 Token 类别，价格可编辑；无价时数据库旧逻辑会写 0 | MVP 不报“总花费”，除非价格来源、版本与覆盖率已齐备；缺价显示“未计价”，不等于免费或订阅账单 |
| 页面 | 请求数／Token／缓存率／费用／成功率，日期趋势、模型/来源明细、请求日志 | MVP 首页保留日期、Agent、模型筛选、核心用量卡、趋势、模型明细、来源覆盖和会话统计；每个数字可查口径 |
| 会话管理 | 每 Agent 一个扫描适配器，统一会话元信息；会话身份与用量解析分层 | MVP 只做会话数量、活跃数、可辨认列表及“关联请求数/Token”；全文、文件与跨机交接后续单独立项 |

源码入口：`src-tauri/src/services/session_usage_codex.rs`、`src-tauri/src/services/usage_stats.rs`、`src-tauri/src/services/sql_helpers.rs`、`src-tauri/src/session_manager/mod.rs`、`src/components/usage/UsageDashboard.tsx`、`UsageHero.tsx`。上述是设计借鉴；移植部分在代码中保留 MIT 归属。

## MVP 范围与验收门槛

1. **数据层：** Windows 本机原生 Codex 请求级 Token 可重复导入，重扫不增长，日志追加只增加新请求；fork、重复快照、跨日、缺时间、未知模型都有固定样本测试。旧累计快照保留作历史证据，不与请求级事实相加。
2. **对账层：** 用同一批完整、已同步的 JSONL 文件与 CC Switch 对比请求数、输入、缓存、输出；差异逐项解释。不能用 CC Switch 尚未同步到末尾的实时库作全量金标准。数据库投影与原生日志再独立复算一次。
3. **产品层：** 首屏最多六个核心指标；1/7/10/15 天切换，日期、Agent、模型筛选，趋势和模型表；明确“0 / 未采集 / 同步中 / 未计价 / 未归属”。会话统计能回答“几条会话、哪条在用、关联多少请求”，但不承诺正文或文件。
4. **发布门槛：** 单元/集成测试、Windows 构建、现有数据备份与迁移、实际浏览器点验、安装版升级后复算均通过，再标记 MVP 发布。任一门槛未过则保持开发分支，不发布正式版。

## 后续迭代顺序

MVP 验收后才进入第二期：增加 Hermes/其他 Agent 的可验证用量适配器与会话身份关联。第三期：可读会话正文、逐轮定位。第四期：文件关联与管理。第五期：跨设备、交接与资源。这些都是候选阶段，不写入 MVP 完成率。

## 已知数据事实与风险

2026-09-26 本机 Codex `sessions` 中约 8.6 千条 token_count 快照；CC Switch 账本约 3.6 千条近期请求，并有按日归档。两者数量不能直接相减：日志有重复和 fork，且 CC Switch 在检查时还有多份文件的同步游标落后源文件。现版 Agent Workbench 的 Codex 卡片主要来自累计快照同日差值，无法作为请求级 Token 基线。接下来必须以受控 fixture 和相同文件边界对账。
