# v0.8.0：可见、可恢复的本机后台

## 用户使用方式

Windows 安装版从开始菜单打开一次即可使用。浏览器直接访问 `http://127.0.0.1:8765/`，不要求密码。后续登录 Windows 时自动启动后台，不自动弹浏览器。关闭浏览器不会停止后台；想查看数据时再次打开收藏的网址或开始菜单入口。

通知区图标一直跟随后台进程存在。Windows 可能将新图标放入右下角“显示隐藏图标”，可以拖到常显区域。双击默认菜单项打开仪表盘，右键可查看状态、刷新、暂停、恢复、重启、查看日志、退出。浏览器标签页也用绿色、黄色、红色图标和标题表示状态，可固定标签页；它不是浏览器扩展，关闭标签页后由通知区图标提供状态。

绿色表示近期采集成功；黄色表示正在采集、暂停、数据更新延迟或来源异常；浏览器红色表示服务无法连接。页面显示最近采集时间，避免把“网页能打开”误当成“数据仍在更新”。暂停不影响查询已归档历史，也不删除历史。退出后台会停止采集，本次登录内不会因正常退出立即自行重开，下次登录仍自动启动。

## 启动、恢复与边界

- 当前用户的 Windows 计划任务运行已安装的程序，参数 `--background`；不用管理员权限，不以 SYSTEM 身份读取其他用户数据。
- 登录触发延迟 10 秒；不设默认的三天运行上限；电池供电不会暂停任务；异常退出由系统间隔一分钟尝试重启。启动入口复用同一实例，不因多次点击再开一套后台。
- 进程启动后立即采集，以后每轮结束等待 120 秒。采集和查询分开；查询通常读取归档，不反复扫描原始来源。文件大小、修改时间和解析器版本决定是否重新归档来源文件；Hermes 同时观察 SQLite WAL。
- 采集错误不会关闭页面，不丢弃已归档事实；下一轮重试并在状态中标明异常。软件没有承诺永久无故障：磁盘损坏、系统任务被禁用、服务线程永久阻塞仍可能需要用户重启或排查。
- `--db` 或自定义 `--port` 是隔离开发入口，不注册真实登录任务。便携版不注册任务，不自动替换安装版。
- Mac 源码提供当前用户 LaunchAgent 的登录启动和异常恢复配置。本次发布只提供 Windows 包，Mac 实机登录、恢复、安装尚未验收。

## 自动更新

安装版后台启动一分钟后检查公开 GitHub Releases，以后每六小时检查一次。只接受较新、非预发布、已上传且具有 GitHub SHA-256 的指定 Windows 安装资产，校验大小和 SHA-256 后才开始安装。检查失败不会中断采集。

更新前复制旧程序并用 SQLite 在线备份保存一致的归档数据库；设置短期维护标记，退出旧进程后执行静默安装。验证新服务的版本健康检查，失败则恢复旧程序和底库并再次启动。失败版本被记录，避免每次检查反复安装；用户可从页面重试或下载公开安装包。维护标记过期后不会永久阻挡登录启动。

更新包尚未 Authenticode 签名；下载校验能发现文件损坏，不等同于发布者代码签名。安装后健康检查验证进程和数据库可用，不等同于所有业务功能的自动验收。

## 数据修正和功能范围

- Token 依原始来源证据统计：新输入、缓存读取、缓存写入、输出可对账到处理总量。缓存参与每次请求的输入，输入明显高于输出可能是正常现象。不是按照用户输入字数估算账单，也不声称未知字段为零。
- Hermes 仍只有会话／模型聚合；无法可靠拆分到日或小时的用量单独显示，不制造热力格子。任意日期查询只能查询实际存在的源记录与归档。
- `external-import-*` 等导入合成任务不再算作已证实的连续运行时段。历史消息继续保留，可信任务边界和消息估算分开显示；运行时间不代表进程 CPU 时间。
- 年／月／周／日热力图、模型分析、会话与文件索引保留。文件路径和操作是来源记录的索引，文件实体未做备份；其他电脑或已消失路径无法在本机打开。
- 显示的是来源记录大小。无法从普通日志推算单个会话独占的进程内存。
- 正文和本地路径只归档至自己的数据库／自己设置的设备同步目录，不上传至项目 GitHub。发布的测试摘要移除用户路径、原文、原始会话 ID 和数据库内容。

## 目录和同步

Windows 程序位于 `%LOCALAPPDATA%\Programs\AgentWorkbench`，数据和日志位于 `%LOCALAPPDATA%\AgentWorkbench\data`，更新快照位于 `%LOCALAPPDATA%\AgentWorkbench\updates`。卸载移除程序和登录任务，保留历史底库和 Agent 原始日志。

两台电脑同步设备专属数据包，不共写一个 SQLite 文件。开发工作区应将 `.git`、`.venv`、`.local`、`node_modules`、`dist` 和 `build` 排除 Syncthing；两端源码以 GitHub 为基准，各自在独立本地仓库开发。冲突副本应先核对，不能拿同步结果当作 Git 合并。

## 发布验收

验收覆盖自动化测试、前端生产构建、真实本机历史数据对账、隔离包启动、Windows 安装、通知区可见状态、计划任务配置、重复启动、显式重启和进程异常退出恢复。逐项实测结果、耗时、资源采样和未测项目见 Release 附件 `verification-v0.8.0.json`。

不将配置检查写成实机测试：没有通过重启整台电脑、72 小时连续运行或 Mac/NAS 双机验收来宣称已经验证。Python 服务和本机归档有实际内存开销，不能承诺只有几十／几百 KB；无 Electron 只是减少一层桌面 Web 容器。
