# 公开路线图与验收门槛

项目以 GitHub Issues 跟踪任务，Milestones 对应 P0、V0.1、V0.2、V0.3。完成代码、通过合成测试与通过实际运行环境是三个不同状态；任何阶段只在验收证据齐全后关闭。

| 阶段 | 已实现的可审查内容 | 仍需完成的工作 |
| --- | --- | --- |
| P0 来源探针 | Windows Codex/Hermes 只读扫描；37,803 条本机 stats_only 事件通过协议校验 | Mac 实际入口/版本、Windows 新任务边界、Hermes 轮次与用量来源证明、脱敏 fixture 与字段映射报告 |
| V0.1 双机 MVP | 单 owner、配对、来源授权、durable outbox、摄入幂等、基础会话/搜索/统计、网页、备份命令、Docker 配置、Windows 便携预览包 | Mac 采集、NAS 构建/内存/恢复、双机断网/重放、精确统计对账、完整来源错误态、正式安装包、自启动、Blob、迁移与 schema 版本管理 |
| V0.2 交接与文件 | 冻结 ZIP、手动续做绑定、限定根目录 stat/sha256 任务 | 交接 UI、目标环境身份细化、文件版本对比与路径映射 UI、交接完整性与大包限制、真实离线跨机验收 |
| V0.3 资源 | 可选进程 RSS/CPU 样本、进程身份键、7 天原始样本删除 | 分钟/小时汇总、资源图、采样开销/内存预算实测、不同入口的进程树识别 |

核心设计偏差：执行规格提出 SQLAlchemy/Alembic 与生成前端 API 类型；目前为了尽快验证事件协议，中心使用 stdlib sqlite3 及手写 TypeScript 类型。该偏差需要在稳定版前通过 ADR 决定保留或迁移，并落实可回滚 schema 迁移。当前 `schema_version=1` 只支持新库，没有升级路径。不能把本仓库当成已验收的 V0.1–V0.3 正式发行版。
