# Agent Workbench 产品、交互与用户任务审核及修改计划

日期：2026-09-26。审核对象：Windows v0.2.3 与当时仓库。状态：**v0.2.3 审核基线**；后续 Windows v0.2.4 的实现与验收结果记录在[验证记录](../verification/README.md)。下文的“当前状态”均指审核时的 v0.2.3，不代表新版现状。

## 1. 结论与审核边界

产品的核心任务来自[原 PRD](../planning/跨Agent工作台_PRD_v0.1.md)：让个人回答“用了多少、做了什么、结果在哪”，并在 Windows、Mac、NAS 之间保留来源和交接证据。当前 Windows 版已经能安装、设置密码、自动发现 Codex/Hermes 记录、入库、显示总览和会话，统计筛选与指标卡也有初步下钻。它是可运行的**统计骨架**，还不是可靠的“活动回看工作台”：**从数字找到会话、读到完整历史、定位一轮、核查产物**这条主路径没有闭合。

本审核按顺序汇总三轮独立视角：产品经理对照 PRD 与[执行规格](../planning/02_EXECUTION_SPEC.md)，UI/UX 对照截图和页面代码，四类模拟用户按任务走查。模拟用户不是访谈，也不是实机可用性测试。本轮复核了仓库、已有[验证记录](../verification/README.md)及用户提供的页面截图；浏览器自动控制连接失败，因此**没有声称完成本轮浏览器点击验收**。本机只有 Windows，Mac/NAS 继续标为未验收。私人源日志和原文不写入公开报告。

### 如果重新设计，我会采用的产品结构

以“证据链”组织信息，而不是以独立的统计卡和日志表组织页面：

```text
日期/设备/Agent/模型筛选 → 当日活动与可信指标
    → 可辨认的会话与活动片段 → 可展开的一轮
    → 用户输入 / AI 回复 / 工具事件 / 用量依据 / 文件证据
    ↔ 可从文件、搜索结果或时间线返回同一轮
```

首页回答“发生了什么、数据截至何时”；会话页回答“这一轮做了什么”；文件页回答“结果在哪里、是否仍存在、依据是什么”。所有页面共享筛选状态与深链。任何指标同时展示**值、口径、覆盖率、未归属部分与来源**；任何“0”都必须与“未采集”“仍在导入”“不可恢复”“待核验”区分。产品不替代原 Agent 聊天界面，也不把无法观察的阅读行为、历史 RAM 或文件关系补造出来。

## 2. PRD 对照：现状与缺口

状态的含义：“已具备”指代码与既有 Windows 验证支持；“部分”指有入口或底层结构但用户任务未完成；“缺失/未验收”指尚无可用链路或实机证据。现有能力仍需要最终浏览器点验。

| 用户任务 / PRD 条目 | 当前状态 | 证据和实际问题 | 用户后果 |
| --- | --- | --- | --- |
| Windows 安装、网页首设、来源自动发现与采集 | 已具备 Windows 基础；来源覆盖部分 | `README.md`、`docs/verification/README.md`、`src/awb/collector.py` | 能进产品并看到记录，但不能由此推论所有源字段完整 |
| 单日/7/10/15 天、设备/Agent/模型筛选和设备对比 | 部分 | `web/src/Overview.tsx` 已实现；会话页隐藏当前筛选，URL 不保留 | 切页后误以为会话丢失，刷新/分享不能复现 |
| 用量、耗时及指标依据 | 部分，Token 可信度待核验 | `src/awb/stats.py` 与 `web/src/Overview.tsx`；依据只能下钻到会话，未到源轮次 | 数字看似精确却难以解释极端比例或独立核对 |
| 按日期找回旧会话与活动 | 部分 | 会话列表有数据；标题大量为“未命名会话”，目录末级易被误当话题；详情默认最早 50 条 | 用户不能辨认目标，点最近会话却先看到很久以前的消息 |
| 全文与逐轮展开 | 部分/缺失 | `stats_only` 历史正文为空；开关只影响以后；`web/src/main.tsx` 平铺消息，轮次为静态文本 | 无法回看“我说什么、AI 回什么”，也无法点某一轮 |
| 时间线与并行关系 | 部分 | `web/src/TimelinePanel.tsx` 能画线、缩短默认列表，但未知结束呈小点；点击只传会话 ID | 看不出时间、状态和任务，也到不了那一轮 |
| 文件产物、路径、大小和来源关系 | 底层表/API 部分存在；产品链路缺失 | `file_events` 当前未形成可用数据；文件栏不可点；“文件 0”未表达覆盖缺口 | 无法从对话找到产物，错误认为没有文件 |
| 来源健康、完整度和隐私 | 部分 | 网页“已连接”仅代表服务连接；来源扫描、索引、正文覆盖未连贯显示 | 无法区分没有活动、还没导入、采集失败或策略未采 |
| 资源占用、跨设备交接 | 底层部分/未验收 | 可选进程样本默认关闭；Mac/NAS 当前无实机 | 不能报告会话历史 RAM，也不能称原 PRD 双机已完成 |

## 3. 数据可信度专项审查

**Token：问题不是单纯的四则运算。** 用户截图中 15 天输入 232,453,414、输出 1,042,368，约 223:1。Codex 来源存在会话累计快照；缓存输入属于输入的一部分，不应再叠加。一次本机只读复算初看与数据库汇总一致，且旧规则下缓存输入占比很高；继续审查发现 12 个子 Agent 日志先写子会话身份，再写继承的父会话元数据，旧适配器错误切换到父身份。复算沿用了同一错误身份规则，故**该一致性不能证明原汇总正确**。必须固定每个文件的原生身份、隔离计数器代际、在备份上修复历史投影后重新对账。旧日志首个余额、跨日缺口和混合来源也须明确展示。此前按文件粗加所得约两倍数字同样不是有效对账结果。

**历史正文：现在大多数记录确实没有可读正文。** 现有数据库约三万条消息中仅很少一部分有正文；来源设置虽然已可选 `full_content`，对旧 `stats_only` 事实不会自动补齐。补采要从仍存在的原生日志只读回填，并先让用户选来源/日期/项目范围、预览条数及隐私影响。不能只清空采集游标重扫：旧消息固定修订键，正文变化可能与同一事件 ID 冲突。需要版本化内容修订、可见进度、脱敏/截断、不可恢复缺口，以及“用户删除后重新扫描也不复活”的验证。

**身份与路径：工作目录不是会话标题。** Codex 适配器把标题写为空，页面用“未命名会话”兜底。截图中的 `github`、`ppt-ppt…` 是来源报告的目录末级；它们不证明话题，也不证明文件由该会话产生。审核时抽查的部分完整路径确实存在，所以不能概称“虚构目录”。界面应标记“源记录的工作目录”，显示完整路径、设备、检查时间和当前可访问状态；会话独立采用可信标题/首句预览/Agent+时间+原生 ID 短码辨认。

**轮次、文件、RAM：必须控制精度。** 消息与 native turn 的关联尚不完整，文件事件当前缺口不能写作“没有文件”。源日志包含工具调用/输出，但采集器目前主要投影消息，建立文件关系需解析成功工具操作并区分创建、修改、读取、引用、仅同目录可能相关。进程 RSS/CPU 可选采样是**进程观察值**，共享进程不能硬分配到会话；未采样的历史内存不可恢复。

## 4. UI/UX 审核：保留、修改与交互契约

可保留：白底低干扰视觉；总览范围切换和设备/Agent/模型筛选；指标卡“查看依据”；多日趋势回单日；最近会话、设备与时间线入口；时间线默认少量行再展开；来源正文策略设置。这些是信息架构的基础，但下钻需接通证据。

| 严重度 | 当前体验 | 修改后的交互契约 |
| --- | --- | --- |
| P0 | 首页、列表和依据弹窗都是“未命名会话”，目录末级被当辨认信号 | 三处使用同一会话识别组件：用户标题 > 来源标题 > 已获授权的首条用户输入预览 > Agent+起始时间+短原生 ID；显示设备、最后活动、轮次、内容覆盖；目录独立标注 |
| P0 | “对话/轮次/文件”外观像标签页却只是 `<span>`；右栏轮次/文件只是文本 | 真正的标签页、轮次按钮和文件详情；鼠标与键盘均可操作；选中状态、焦点与返回位置明确 |
| P0 | “正文未采集”占满详情但无补救 | 详情顶部显示可读 X/Y、原因、当前策略、历史补采入口与进度；不能恢复时直接说明 |
| P0 | 会话页沿用隐藏筛选；页头“已连接”含义过宽 | 会话页显示可修改/清除的日期和来源筛选；分开显示服务可达、源扫描、入库和索引水位 |
| P1 | 指标只到会话；时间线只到会话，圆点需靠悬停猜测 | 指标定位贡献轮次；时间线行内有 09:13–09:27 / 结束未知、任务名、设备、Agent、状态与时长；点击落到轮次并高亮 |
| P1 | 窄屏隐藏右栏，移动端列表排在详情前 | 小屏改“列表 → 详情”导航；轮次、文件、资源作为可见标签页，保留返回入口 |
| P1 | 搜索结果缺设备、日期、匹配片段和消息定位；短中文搜索不完整 | 结果显示命中原文片段及来源，点到消息；1–2 字中文按受限范围检索并提示范围/上限 |
| P2 | 弹窗、导航与状态主要依赖视觉样式和悬停 | 对话框焦点管理、Escape、标签页键盘语义、`aria-current`、可见焦点及 200% 放大验收；设计参考 [W3C APG Tabs](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/)、[Accordion](https://www.w3.org/WAI/ARIA/apg/patterns/accordion/) 与 [Dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) |

推荐页面：总览首屏保留 4–6 个核心量和“数据截至/覆盖”摘要；单日下面用分组时间线，多日先用趋势，点某天再看片段。会话页左侧按日期列会话及当日活动，中间按轮次折叠用户/Agent/工具过程，右侧为可收起的证据面板。每个轮次显示开始、结束或缺失原因、用量、关联文件和原生来源定位；文件详情显示动作、路径、大小、当前可访问状态、检查时间和关联证据。

## 6. 修改计划、依赖与验收

优先级按用户任务失败的影响排序。一个阶段完成需要**代码、真实数据对账、安装版浏览器操作**三种证据；单有单元测试或打包通过不算完成。

### P0 — Windows 核心回看闭环（下一稿）

1. **P0-01 先建可信账本与状态模型。** 定义每项指标的来源事件、原生身份、计数器代际、缓存输入包含关系、跨日未归属与覆盖率；修复逐请求/累计快照混合的重叠风险。将 0、未知、待核验、未采集、导入中区分为数据状态。验收：一组真实 Codex 和 Hermes 脱敏样本逐条复算、重传不增加、跨日不伪分配；首页可查看来源和未分配量；未证实时不呈现伪精确数字。
2. **P0-02 历史内容回填与隐私闭环。** 只读发现可恢复范围，网页选择来源/日期/项目，预览隐私与数量后启动补采；版本化修订、进度、错误与删除不复活。验收：同一历史会话的已授权用户/AI 正文可读，未保存或被遮蔽段有原因；多次补采幂等，删除后重扫不复活；未授权来源仍不采正文。
3. **P0-03 会话身份与日期导航。** 统一标题优先级、支持用户改名、完整目录元数据、活动日期索引；最近会话默认进入最近活动，选某日进入当天活动，另有“查看完整会话”。验收：十条无来源标题记录仍可区分；跨日旧会话在活跃日可找到；页面不会默认把最新会话定位到最老 50 条。
4. **P0-04 轮次详情和深链。** 完成消息与原生轮次的证据映射、按轮分页、用户/AI/工具步骤折叠、目标轮附近加载；URL 带日期/筛选/session/run/message；指标依据和时间线都进入准确轮次。验收：从总览至目标轮最多两次操作；长会话翻页不重不漏；刷新/浏览器返回保留定位；无法映射的消息标“轮次待归属”而非伪归属。
5. **P0-05 会话页可见筛选与来源状态。** 显示当前日期/设备/Agent/模型、清除/更改入口、扫描与索引截至、正文覆盖。验收：切页与刷新后范围可见；源停止扫描时不能只显示“已连接”；空结果能解释是筛选、导入还是确实无活动。

### P1 — 结果与时间关系闭环

6. **P1-01 文件证据链。** 从成功的工具操作和明确引用采文件事件；在授权根范围内按需读取大小、mtime、可访问状态，并保留证据等级；文件与轮次双向跳转。验收：一条真实创建/修改路径可复核；一个文件多次修改不计为多个文件；没有事件时显示“文件证据未采集”，不显示“无产物”。
7. **P1-02 单日时间线和多日趋势。** 单日按设备/Agent 组织活动泳道、压缩噪声，行内直接给出起止/状态/任务/来源；未知结束有文字说明；多日先看逐日趋势，跨日活动在两天可定位。验收：不悬停能说清哪台设备何时做了什么；点击片段能到对应轮。
8. **P1-03 搜索与移动端。** 标题/已授权原文/文件路径检索，结果有来源与匹配片段，支持 1–2 字中文有界回退；窄屏保留轮次/文件入口。验收：从短中文搜索结果能点到消息；800px 与手机宽能完成列表→轮次→文件→返回。

### P2 — 明确边界后的扩展

9. **P2-01 资源页。** 用户主动开启进程采样后展示观察值、采样时间、共享进程说明、峰值和缺口；不推断未采集的历史或“某对话独占多少 RAM”。
10. **P2-02 跨机与交接。** 在真实 Mac/NAS 可用后逐项做来源探针、身份归属、离线重放、备份恢复、文件映射与交接；通过原 PRD AT01/03/04/10/13/14 等真实用例后再宣称双机完成。目前维持“未验收”。
11. **P2-03 稳定版工程门槛。** 为当前数据库 schema v1 建立可回滚迁移；决定是否保留 sqlite3/手写类型与原执行规格的 SQLAlchemy/Alembic 偏差；补安装版升级、自动更新/签名与灾备验证后才使用“完整稳定版”措辞。

### 下一稿最小可演示路径与发布门槛

用一条真实 Codex 历史会话和一条 Hermes 历史会话，从总览/搜索辨认 → 进入所选日期 → 查看可恢复全文或明确缺口 → 展开某一轮及用量依据 → 查看文件证据或明确“尚未建立证据” → 返回原筛选。先做只读备份与可回滚迁移；每个修改在脱敏 fixture、实际来源抽样、安装版浏览器键盘/鼠标操作中分别通过。若 Token 对账尚未完成，保留“待核验”状态，不把“数字能相加”当成准确性验收。浏览器实测与用户任务走查完成后，才重新评估 Windows 版是否可称为完整可用。

## 7. 风险、取舍与待确认事实

- 历史原文可能已被源平台删除、压缩或从未保存；补采必须显示可恢复范围，不能承诺全部找回。正文采集提高隐私与存储成本，因此维持按来源/范围选择、可删除且不复活。
- 原生日志可有多段元数据、转调用或重放；Token、轮次、文件都必须按稳定来源身份对账，不能把粗略行数相加当事实。
- “工作目录存在”与“文件由会话产生”是两种不同证据；当前目录是否可访问会变化，必须记录检查时间。
- 共享 Agent 进程的 RSS 不能精确分摊给一个会话；跨机后的同一任务也不自动等于同一原生会话。
- 当前只有 Windows；Mac/NAS 的采集格式、路径权限、网络和资源预算仍需实机验证。发布范围可先是优秀的 Windows 单机产品，不能把原跨机 PRD 在文案中标为完成。
