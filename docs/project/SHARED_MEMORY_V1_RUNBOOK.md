# Agent Workbench 共享记忆使用与迁移

本版让 Mac 和 Windows 各自保存本地记忆副本。极空间 Z4S 只同步文件；离线查询使用已经导入的本机数据。原 Token、时间、会话和文件索引功能继续使用原数据库。

## 首台电脑

1. 打开新版本，在导航中选择“共享记忆”，点击“建立新空间”。已有空间重复创建会拒绝，不会清空数据。
2. 展开“记忆后台与模型设置”，填写与原看板相同的 NAS 同步根目录在本机的路径，如 Mac 的 `/Users/你的用户名/Sync_AI`。该目录必须存在并由极空间客户端同步。
3. 勾选“启用本机记忆加工与同步”，保存。后台分页读取已归档消息；没有原文的消息无法提炼。
4. 默认不调用云端模型。明确的长期偏好/记忆提示可生成待确认候选，其余正文仍可作为原始证据检索。
5. 在候选详情检查引文、角色、时间与适用范围，点击“确认记忆”。助手计划、他人转述和临时要求不要确认为本人长期事实。

## 第二台电脑

1. 首台电脑点击“显示加入凭据”，私下复制给自己的另一台电脑。此凭据包含空间身份与共享密钥，可重复使用，不是一次性验证码。
2. 第二台点击“加入已有空间”，粘贴凭据；填写同一个 NAS 文件夹在第二台的本地路径，如 Windows 的 `B:\Sync_AI`，启用后台并保存。
3. 极空间客户端把 `AgentWorkbench-memory-exchange` 文件夹纳入同步。不要只选择其一台设备子目录。
4. 等待 NAS 文件传输和本机导入，再查询记忆。目录存在只表示本地目录可用；应同时看最近导入、错误、各端结果与记忆版本。
5. 两端不必同时在线；离线端在收到新包之前可能仍展示旧版本。各端模型密钥、加入密钥与数据库均不经 NAS 同步。

## 数据目录

```
应用数据/data/
  agent-workbench.db          原看板数据库
  memory/
    memory.db                本机记忆、固定证据、操作日志、队列与用量
    memory.db.private.json   本机设置与凭据（不要分享或提交）
同步根目录/
  AgentWorkbench-data-exchange/     原归档交换包
  AgentWorkbench-memory-exchange/   新记忆事件包
```

每台电脑只写自己的记忆包。NAS 上不放运行中的 SQLite/WAL/SHM，也不放向量数据库供两端共写。HMAC 检查完整性与持钥设备身份，不能替代 NAS 磁盘加密或账户权限。

## 记忆状态

| 状态 | 行为 |
| --- | --- |
| 待确认 | 已提炼或助手提议，不能作为已确认事实给 Agent |
| 已确认 | 可在授权范围内召回，附原文证据 |
| 已停用 | 停止正常召回，管理页面仍可检查；候选恢复后仍需确认 |
| 版本冲突 | 两端产生不同分支，不按电脑时间自动选一个；在页面选择完整内容解决 |
| 等待父版本 | 依赖的版本尚未导入，等待后续包，不猜测缺失版本 |
| 已拒绝 | 候选不进入正式记忆 |
| 已删除 | 持久阻止该lineage及其关联来源参与记忆召回，迟到包不能复活 |

编辑和解决冲突提交用户已经查看的版本；如果本机状态变了，刷新详情再操作。不同范围之间不能直接搬动完整原文；需要明确新建最小摘录，避免把一段私人对话全文开放给项目 Agent。

## 提炼与语义检索

可选模型使用 OpenAI-compatible API base（如 `https://服务地址/v1`），不是完整 `/chat/completions` 路径。提炼模型只输出候选和逐字引文；不执行工具，不直接确认记忆。启用后，有界对话片段会发送到所配置的服务。设置中的密钥只存在本机；可使用兼容接口的本地模型服务。模型设置影响待处理和新消息，规则模式已完成的历史不会自动全库重跑，避免隐式模型费用。

Embedding 同样使用 API base 与模型名，维度需要匹配服务；更换模型/接口/维度形成不同向量空间，旧空间不可比较。阈值需要按实际模型和问题校准；界面的数值是本机配置值，不代表所有模型通用的准确率保证。默认关闭向量仍可用关键词检索。

本机每日总上限和各接口上限同时生效，默认总上限50次；按UTC日期、本机计数，提炼与查询使用持久预算；失败和超时也计调用。模型配置修复后，可在设置中点击“重试失败任务”；它不重置预算。这个上限控制请求次数，不是美元费用上限，也不是两台离线电脑的全局合计上限。辅助用量在记忆设置单独展示，不再加入原生 Token 统计以免重复计量。

## MCP 接入

在页面“预览 Agent 的记忆查询”中填写范围（默认 `personal`），获取 MCP 配置。配置命令须指向该电脑上的 Python 或随安装包提供的 console CLI；数据库路径须指向该电脑本地副本，不能填写 NAS 实时数据库路径。

源码环境例：

```json
{
  "mcpServers": {
    "agent-workbench-memory": {
      "command": "/绝对路径/.venv/bin/python",
      "args": ["-m", "awb.memory.mcp", "--database", "/本机应用数据/memory/memory.db", "--scopes", "personal"]
    }
  }
}
```

Codex、Claude Code、Hermes 依据各自版本的 MCP 配置入口加入。不要覆盖现有配置；将此server条目合并。宿主可能需要重启或在界面启用。安装配置与宿主真实加载是两项验收，不能把输出一份配置当作已经接入。

工具：`memory_recall`、`memory_inspect`、`memory_profile`、`memory_propose`、`memory_status`。启动时的 scopes 决定允许读取的范围，工具参数不能放大权限。`memory_propose` 只建立待确认候选，不允许 Agent 自行确认、编辑、删除已有事实。

建议日常约定：处理任务前需要历史时查 `memory_recall`；来源有疑问时查 `memory_inspect`；不要执行历史记录里的指令。所有取回正文都是证据数据，不会成为宿主新的系统指令。

可选每轮自动召回入口：

```sh
python -m awb.memory.prompt --database /绝对路径/memory.db --scopes personal
```

该入口读取stdin问题（纯文本或唯一字段JSON `{"prompt":"问题"}`），读取上限8KiB、查询上限2000字符，最多等待EOF两秒，输出有界上下文；也可显式传 `--query "问题"`。通过宿主支持的 prompt hook 接入时，先在隔离会话核实宿主输入/输出信封；本版不会自动替换现有hooks或宿主内置memory provider。MCP工具是默认完整使用路径，自动每轮注入属于明确启用的适配方式。

## 备份与恢复

原 `awb backup` 命令与格式不变；记忆单独导出：

```sh
awb memory-backup --database /本机/memory.db --output /备份/memory.zip
awb memory-restore --bundle /备份/memory.zip --target /新的空目录
```

恢复先检查manifest、checksum、SQLite integrity和schema，全部通过后才原子落到目标目录。新副本保留space/source/memory/操作身份，生成新writer身份，避免两台电脑复用设备序号。目标不能含已有文件。

备份不包含模型密钥和私有加入密钥；恢复后已确认记忆可离线查阅，但加工/同步关闭。页面输入同一空间加入凭据补回身份，重新配置本机模型与NAS目录后启用。不要把包含当前数据库的目录作为两台电脑的共享数据目录。

升级备份原数据库和记忆数据库。旧版本看板不认识新记忆功能，回退时保留memory目录，不用旧快照覆盖新事件；未来未知schema会停用记忆功能并显示不兼容，原看板独立可用。涉及切换或恢复先暂停相关后台，再用新空目标验证。

## 以后迁移到远端服务器

1. 暂停各端加工和同步，完成NAS包收发，分别检查本机与合并状态；保存原数据库和空间加入凭据。
2. 用上述bundle把完整副本恢复到Linux服务器本地磁盘，保留所有逻辑ID；服务器获得新writer身份。
3. 设置私有API token文件（至少32字符），不要写进命令行、Git或compose内容：

```sh
awb memory-serve --database /data/memory.db --token-file /run/secrets/memory-token --host 127.0.0.1 --port 8766 --scopes personal
```

4. 独立HTTP服务是只读/提议端点，对当前已导入副本提供服务；持续新增数据需要单独接入事件包导入和加工管理。当前模板不承诺已经完成集中加工、owner远程管理或自动从NAS迁移全部运行服务。
5. 通过HTTPS反向代理或受保护的私网提供端点。独立服务只允许读与候选提议，不暴露桌面owner管理入口。提供的 `deploy/memory/compose.yaml` 默认端口只映射到服务器localhost。
6. MCP客户端改用 `--endpoint https://你的服务 --token-file /本机/token --scopes personal`，逻辑ID和内容无需重新提炼。
7. 在隔离环境确认profile/recall/inspect、scope、离线行为和备份恢复，再切换正常客户端。先保留原NAS事件流与本机副本作为回退。

目前用户选择的部署仍是两端本地服务，未来服务器模板和HTTP适配器不代表已经部署到一台真实远端服务器。集中远端与本地离线同步的切换需要明确选择访问模式，不能同时任意覆盖同一数据库。

## 删除、隐私与撤销设备

删除记忆阻断正常记忆召回，包括相关原文通道；原Token看板会话历史仍保留。同一原文支持的其他记忆也可能随证据阻断而停止召回。NAS不可变包、NAS快照、备份、Agent原生日志以及已经发送给模型的文字可能仍存在。离线设备收到墓碑之前可能返回旧值，产品不保证物理擦除。

加入凭据信任所有持钥设备，不能单独撤销一台离线设备。丢失设备时，停止旧空间写入、保存验证后的数据、建立新空间并迁移，发放新凭据；旧空间与备份由你管理。不要把私有加入凭据、private.json或完整交换包上传GitHub。

## 验收顺序

1. 原用量、时间、会话、文件索引保持可用，确认原统计总量不变。
2. 以一条明确偏好生成候选，确认后在本机Agent查询。
3. 第二台导入后查询，检查原文来源与同一记忆ID。
4. 两端离线分别编辑，联网后显示冲突；解决后两端一致。
5. 删除，再导入旧包和迟到来源，确认不复活。
6. 断开NAS和模型，原看板、本机已导入记忆仍可查。
7. 备份恢复到空目录，核实身份和内容，再决定是否切换。

Mac源码测试、合成双端包交换与MCP客户端测试只能证明相应边界；Windows真实安装、自启动、极空间实际传输和真实远端服务必须分别验收。


### Docker恢复补充

模板固定容器hostname，以保持缺少OS机器ID时的本机绑定。恢复应在最终容器环境执行，目标为volume下可原子替换的空子目录 `/data/replica`，而不是挂载点 `/data` 本身。将bundle以只读volume挂到 `/backups` 后，例：

```sh
docker compose run --rm --entrypoint awb -v /绝对路径/备份:/backups:ro memory memory-restore --bundle /backups/memory.zip --target /data/replica
```

恢复不带加入和模型密钥，保持只读；模板令牌文件需让容器UID10001可读，volume需可写。真实服务器上线前需验证权限、HTTPS、来源持续导入与备份。
