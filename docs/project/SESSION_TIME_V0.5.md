# 会话与运行时间口径（v0.5.0 测试版）

## 查询对象

页面只读取运行工作台的这台电脑上可见的 Codex、Claude Code 和 Hermes 原始记录。所选日期采用香港时区；跨午夜区间在每天边界裁切。会话列表展示当天有用户／Agent 文字消息，或有已完成运行区间的会话。打开会话后按当天消息时间列出文字内容；工具调用与工具输出尚未纳入文字对话面板。索引只保留时间、定位信息和最多 160 字的预览，正文打开时从源文件／Hermes 数据库读取。原始记录只读。

## 时间计算

| 指标 | 算法 | 含义 |
|---|---|---|
| Agent 累计 | 每段运行与查询范围相交部分的时长之和 | 并行任务分别计时，例如两个 Agent 同时运行 10 分钟计 20 分钟 |
| 自然经过 | 所有相交区间的时间并集 | 上例计 10 分钟；不是人的专注工作时间 |
| 各 Agent 去重 | 同一 Agent 的区间并集 | 同一 Agent 的并行会话不会重复计算 |
| 已证实 | 有开始、完成与源记录 `duration_ms` 的 Codex 顶层任务 | 不包含正在运行、无结束事件和子任务 |

热力图颜色按每格的自然经过时间；悬停同时显示 Agent 累计、已证实和区间数。跨午夜区间会分别裁切到相邻两天，因此每天格子的时间可与整个日期范围对账（毫秒取整可能有微小差异）。

## 来源可信度

- **Codex**：有配对的顶层 `task_started`／`task_complete` 时，优先使用完成事件的 `duration_ms`。有对话但没有完整任务事件的会话，按用户消息到下一条 Agent 文字回复估算；会在时间轴以斜纹显示。
- **Claude Code**：本机 JSONL 保存消息时间、用户／助手文字和部分最终回复标记，但当前没有与 Codex 等价的可靠运行开始／结束事件。因此从用户文字到最终 Agent 回复估算。
- **Hermes**：`sessions.started_at`／`ended_at` 是整个会话生命周期，可能包含闲置。采用用户消息至 `finish_reason=stop` 的 Agent 回复估算；计划任务也会纳入，不能等同于人与 Agent 的交互时间。
- 估算只纳入大于零且不超过六小时的闭合片段；超长或没有回复的片段不进入时间总量。会话消息仍可查询。界面分开显示已证实与含估算总量。

时间筛选按 Agent 生效。模型筛选只用于 Token 用量：可靠的逐运行模型归属尚未建立，时间卡片和时间热力图不随模型下拉框过滤。

## Mac 数据核验与跨设备

2026-09-28 在 Mac 上只读核验到 Codex 完成事件包含 `turn_id`、开始／完成时间和 `duration_ms`；Claude JSONL 有消息时间但缺可靠运行事件；Hermes 数据库有消息时间与最终回复标记。Mac 当日真实索引包含 252 个 Codex 文件、87 个 Claude 文件，Hermes 数据库可读。Claude 当前 Mac 原始记录没有 9 月 28 日的可计算片段，不能凭空填数。

Mac 与 Windows 尚未同步。这一版的时间与 Token 只代表当前电脑能读取的日志。未来同步应上传带设备、原生会话／事件标识的增量记录，在聚合端去重，再跨设备求区间并集；离线设备恢复后补传，不能把两机现成的“自然经过时间”简单相加。同步前保留每机独立视图，并处理可能被复制到两机的同一日志。
